# ตั้งค่าบัญชีครู/นักเรียน + ฐานข้อมูลจริง (Supabase + Vercel)

ถ้ายังไม่ได้ตั้งค่าตามนี้ เว็บจะทำงานแบบเดิม คือบันทึกเฉพาะในเบราว์เซอร์ และไม่มีปุ่มเข้าสู่ระบบ
ทั้งหมดใช้เวลาประมาณ 25 นาที ไม่ต้องเขียนโค้ด และไม่ต้องแก้ไฟล์ SQL

## ส่วนที่ 1 — Supabase (ประมาณ 15 นาที)
1. เข้า https://supabase.com → กด **Start your project** → สมัคร/เข้าด้วยบัญชี GitHub
2. กด **New project**
   - Name: `learnloom`
   - Database Password: กด **Generate a password** แล้วจดเก็บไว้เอง (ไม่ต้องส่งให้ใคร)
   - Region: **Southeast Asia (Singapore)**
   - กด **Create new project** แล้วรอ 1–2 นาที
3. เมนูซ้ายมือ เลือก **SQL Editor** → กด **+ New query**
   - เปิดไฟล์ `supabase/migrations/20261103000000_phase1_core.sql` บน GitHub
     (https://github.com/spn2328/LearnLOOM/blob/feat/platform-supabase/supabase/migrations/20261103000000_phase1_core.sql)
   - กดปุ่ม **Copy raw file** (ไอคอนแผ่นซ้อน มุมขวาบนของไฟล์)
   - วางลงในช่อง SQL Editor → กด **Run** (มุมขวาล่าง)
   - ต้องขึ้น `Success. No rows returned` ถ้าขึ้นสีแดง ให้แคปหน้าจอส่งให้ผู้พัฒนา
   - Run ไฟล์นี้ **ครั้งเดียว** (Run ซ้ำจะขึ้นว่า already exists ซึ่งไม่ทำให้ข้อมูลเสีย)
4. เมนูซ้าย **Authentication** → **Sign In / Providers** → กดที่ **Email**
   - **ปิด Confirm email** แล้วกด **Save**
   - ต้องปิด เพราะนักเรียนเข้าด้วย รหัสห้อง + ชื่อเล่น + PIN โดยไม่มีอีเมลจริง และระบบอีเมลฟรีของ Supabase ส่งได้น้อยมาก
5. เมนูซ้าย **Project Settings** (รูปเฟือง) → **Data API** (บางเวอร์ชันชื่อ **API**) → คัดลอก **Project URL** (`https://xxxx.supabase.co`)
6. **Project Settings** → **API Keys** → คัดลอก **anon public** key (ขึ้นต้นด้วย `eyJ…` หรือ `sb_publishable_…`)
   - ⚠️ ห้ามใช้หรือส่งต่อ **service_role / secret** key
   - anon key เป็นค่าสาธารณะ เบราว์เซอร์ของทุกคนเห็นได้อยู่แล้ว สิทธิ์ทั้งหมดถูกตรวจในฐานข้อมูล (Row Level Security)

ไม่ต้องตั้งรหัสครูใน SQL: **ครูคนแรกที่สมัครบนเว็บเป็นคนตั้งรหัสครู** (อย่างน้อย 6 ตัว) ระบบจะจำไว้
ครูคนต่อไปต้องใช้รหัสเดียวกัน ดังนั้นหลัง deploy ให้เจ้าของสมัครบัญชีครูเป็นคนแรกทันที

## ส่วนที่ 2 — Vercel (ประมาณ 10 นาที)
1. เข้า https://vercel.com → เลือกโปรเจกต์ของเว็บ (learnloom)
2. แท็บ **Settings** → เมนูซ้าย **Environment Variables**
3. เพิ่มทีละตัว (ติ๊ก Production, Preview และ Development ทั้ง 3 ช่อง) แล้วกด **Save**
   | Key | Value |
   |---|---|
   | `VITE_SUPABASE_URL` | Project URL จากข้อ 5 |
   | `VITE_SUPABASE_ANON_KEY` | anon public key จากข้อ 6 |
4. แท็บ **Deployments** → รายการบนสุด → ปุ่ม `⋯` → **Redeploy** (ค่าใหม่จะมีผลหลัง deploy ใหม่เท่านั้น)
5. เปิดเว็บ แถบด้านบนต้องมีปุ่ม **เข้าสู่ระบบ** ถ้าไม่มี แปลว่าค่ายังไม่เข้า ให้ตรวจชื่อ Key ว่าสะกดตรงทุกตัว

เครื่องผู้พัฒนา: คัดลอก `.env.example` เป็น `.env.local` แล้วใส่ค่าเดียวกัน (ไฟล์ `.env.local` ห้าม commit)

## ส่วนที่ 3 — ทดลองใช้จริง (ประมาณ 15 นาที ทำบนเว็บที่ deploy แล้ว)
1. **ครู**: กด เข้าสู่ระบบ → แท็บ **ครู** → "ยังไม่มีบัญชีครู? สมัคร" → ใส่ชื่อที่แสดง อีเมล รหัสผ่าน และ **ตั้งรหัสครู** → สมัครบัญชีครู
2. ครูกด **📊 แดชบอร์ดครู** → พิมพ์ชื่อห้อง (เช่น ม.6/1 เคมี) → **+ สร้างห้อง** → ได้ **รหัสห้อง 6 ตัว**
3. **นักเรียน** (ใช้มือถือหรือเบราว์เซอร์อีกตัว): กด เข้าสู่ระบบ → แท็บ **นักเรียน** → ใส่รหัสห้อง + ชื่อเล่นสมมติ + PIN 4–6 หลัก → ติ๊กรับทราบ → เข้าสู่ระบบ
4. นักเรียนเรียน C01 ไปสักข้อ → ป้ายด้านบนต้องเปลี่ยนเป็น **ซิงก์แล้ว**
5. ครูกด **↻ โหลดข้อมูลล่าสุด** → ต้องเห็นนักเรียน ความคืบหน้า และ "ดูรายละเอียด" ที่บอกเส้นทางและเหตุผล
6. นักเรียนออกจากระบบ → เข้าใหม่ด้วยรหัสห้อง ชื่อเล่น PIN เดิม (หรือเปิดอีกเครื่อง) → กด **เรียนต่อจากจุดเดิม** ต้องกลับไปที่เดิม
7. ใส่ PIN ผิดด้วยชื่อเล่นเดิม → ต้องขึ้นว่า PIN ไม่ตรง (ไม่สร้างบัญชีใหม่ทับ)

## นักเรียนลืม PIN
ตอนนี้ยังไม่มีปุ่มรีเซ็ต PIN ให้นักเรียนเข้าด้วยชื่อเล่นใหม่ (เช่น `ฟ้า2`) แล้วเริ่มใหม่
ถ้าต้องการลบบัญชีเดิม: Supabase → **Authentication** → **Users** → ค้นหาไม่ได้ด้วยชื่อเล่น (อีเมลถูกแปลงเป็นรหัส) จึงให้ดูวันเวลาที่สร้าง แล้วลบ ข้อมูลของบัญชีนั้นจะถูกลบตามไปด้วย

## สิ่งที่ฐานข้อมูลตรวจเอง (Row Level Security)
- นักเรียนเห็น/เขียนเฉพาะข้อมูลตัวเอง ไม่เห็นข้อมูลเพื่อน
- ครูเห็นเฉพาะนักเรียนที่อยู่ในห้องที่ตนสร้าง และอ่านได้อย่างเดียว
- เป็นครูได้ทางเดียวคือรหัสครู รหัสห้องสร้างโดย server
- คำตอบ (`answer_events`) เพิ่มได้อย่างเดียว แก้/ลบไม่ได้ ส่งซ้ำไม่เกิดแถวซ้ำ ทำใหม่เป็นครั้งที่ 2, 3 แยกกัน ครั้งแรกไม่ถูกทับ
- คนที่ไม่ได้เข้าสู่ระบบ ถามได้อย่างเดียวว่ารหัสห้องนี้คือห้องชื่ออะไร
- ตรวจด้วย `pnpm test:db` (Postgres จำลองในเครื่อง ยังไม่ใช่ Supabase จริง)

## ข้อควรรู้ด้านความปลอดภัยของ PIN
- PIN 4 หลักเดาได้ถ้ามีคนตั้งใจ Supabase จำกัดจำนวนครั้งที่เข้าสู่ระบบผิดต่อเครื่อง/IP อยู่แล้ว แต่ไม่ได้ล็อกบัญชี
- ข้อมูลที่เก็บเป็นชื่อเล่นและคำตอบเท่านั้น ความเสี่ยงจึงต่ำ แต่ควรแนะนำให้นักเรียนใช้ PIN 6 หลักที่ไม่ใช่ 123456 หรือวันเกิด
