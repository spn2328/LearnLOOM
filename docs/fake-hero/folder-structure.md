# โครงสร้างโฟลเดอร์และแนวทางจัดระเบียบ

## สถานะจริง
โฟลเดอร์เอกสาร docs/fake-hero/ ในชุดนี้ถูกเพิ่มเพื่อรวบรวมแผน ส่วนโครงสร้างด้านล่างเป็นข้อเสนอสำหรับขั้นพัฒนา ยังไม่ใช่ไฟล์ที่สร้างไว้จริง

| ตำแหน่งที่มีอยู่ | หน้าที่ | ข้อควรระวัง |
|---|---|---|
| app/ | route และ API ของระบบเต็ม | ผูกกับการ build ระบบเต็ม |
| components/ | ส่วนแสดงผลเดิม | ตรวจ import ที่ใช้ร่วมกันก่อนแยก |
| demo/ | จุดเข้าและตัวจัดเก็บของ Vercel demo | ตรวจ vite.demo.config.ts และ vercel.json ก่อนแก้ |
| lib/ | เนื้อหา กติกา ประมวลผลและจัดเก็บ | รักษาคลังเดิมและข้อความต้นฉบับ |
| public/ | ภาพ ฟอนต์ service worker | ตรวจ path และ cache หากเปลี่ยน |
| db/, drizzle/ | schema และ migrations ระบบเต็ม | ไม่ย้ายหรือลบโดยไม่มีแผน |
| scripts/ | build, checks และเครื่องมือ | ตรวจผลกระทบก่อนเปลี่ยน |
| docs/ | เอกสารโครงการ | เก็บแผนใหม่ใน docs/fake-hero/ |

## โครงสร้างที่เสนอเมื่อเริ่มพัฒนา

```text
LearnLOOM/
├── docs/fake-hero/          แผน ขอบเขต flow และสถานะ
├── demo/                    จุดเริ่มเดโม Vite และ storage adapter เดิม
├── features/fake-hero/      เสนอสร้างเมื่อเริ่มพัฒนา
│   ├── content/             ข้อมูลฉาก Q01/Q01-E และเฉลยที่ยืนยัน
│   ├── components/          Story, กิจกรรม, คำถาม, บทช่วย, สรุป
│   ├── flow/                กติกาเปลี่ยนหน้า/กฎเส้นทาง/ชนิดข้อมูล
│   └── storage/             adapter ข้อมูลเฉพาะเดโมเมื่อจำเป็น
├── public/fake-hero/        ภาพและเสียงที่ได้รับอนุญาตเมื่อมีจริง
└── components/, lib/, app/, db/, drizzle/, scripts/  ของเดิม
```

แผนนี้เสนอเพิ่ม feature ใหม่แบบค่อยเป็นค่อยไป ไม่ย้ายโค้ดเดิมทั้งหมด: สำรวจ imports เส้นทาง assets, service worker, script และทั้งสอง build ก่อนเปลี่ยน; ย้ายทีละส่วนพร้อมทดสอบ. ตรวจ SOURCE_MANIFEST.json และ build/, vendor/ ว่าเป็น inputs หรือ output ก่อนดำเนินการ ห้ามลบโดยคาดเดา
