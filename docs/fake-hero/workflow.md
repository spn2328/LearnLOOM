# Workflow พัฒนาและตรวจเดโม

1. อ่าน state.md, plan.md, demo-flow.md และไฟล์ต้นฉบับที่เจ้าของยืนยัน; ตกลงงานย่อยพร้อมผลลัพธ์ที่ตรวจได้
2. ตรวจ main และสร้าง branch สำหรับงาน; ตรวจสภาพเว็บเดิมและบันทึก baseline โดยไม่เปิดเผยข้อมูลนักเรียน
3. เลือกใช้ของเดิมหลังตรวจ dependency และผลกระทบต่อ Vercel demo กับ full-stack; พัฒนาเฉพาะเรื่องที่ตกลง
4. คงข้อความคำถาม ตัวเลือก เฉลยและเรื่องราวที่ได้รับการยืนยัน; เสนอข้อผิดพลาดให้ครูตรวจโดยไม่แก้โดยพลการ
5. ตรวจกรณีใน plan.md, สถานะว่าง/ย้อนกลับ, ชื่อฉากและสูตร; แยกผลครั้งแรกจากผลหลังช่วย
6. รัน pnpm install --frozen-lockfile, pnpm test, pnpm typecheck และ pnpm build:demo ในสภาพแวดล้อมที่รองรับตาม README; หากแก้ระบบเต็มตรวจ pnpm build และส่วนที่เกี่ยวข้องเพิ่ม บันทึกผลตามจริง
7. ทดลองใน browser และบนคอม/iPad จริงที่ตั้งใจใช้สาธิต รวมการแตะและอ่านภาษาไทย ถ้าทำไม่ได้ระบุข้อจำกัด
8. อัปเดต state.md และเปิด PR ให้ตรวจ ขณะนี้ยังไม่ดำเนิน Phase 4/5 หรือเผยแพร่ใหม่

การบันทึก: ใช้ข้อมูลตัวอย่างหรือชื่อเล่นในเครื่อง; ห้ามใส่ข้อมูลนักเรียนจริงลง repository. ไม่กล่าวอ้างว่าระบบมีฐานข้อมูลกลาง ออฟไลน์ หรือซิงก์ได้จนพัฒนาและทดสอบสำเร็จ
